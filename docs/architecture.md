# Архитектура «Моей системы»

Источник требований: `/Users/birzhansovetov/Downloads/CODEX_PERSONAL_PLATFORM.md`.

## Продуктовая цель

Платформа помогает человеку развиваться в шести сферах жизни. Для каждого поддерживаемого маршрута она предоставляет готовые основные материалы и конкретный следующий шаг внутри сайта: пользователю не нужно самостоятельно искать упражнения, рецепты или уроки. Если маршрут не подходит, пользователь может изменить ответы, цель или доступные условия и выбрать подходящий вариант; перед заменой плана показывается, что изменится, а история выполненного сохраняется. Если подходящих проверенных материалов пока нет, раздел сообщает об этом прямо.

Согласованные шесть сфер: «Здоровье» (спорт и питание), «Обучение» (включая программирование и книги), «Профессия», «Языки», «Финансы», «Личное» (включая дневник). Ни одно направление исходного задания при группировке не исключается.

## Согласовано с пользователем

- Один репозиторий с собственным backend на Python и FastAPI.
- Frontend: React, TypeScript, Vite, React Router, TanStack Query, CSS Modules.
- База данных: управляемый PostgreSQL на бесплатном тарифе Neon.
- Файлы: S3-совместимое Neon Object Storage на бесплатном тарифе.
- Backend: модульный монолит, SQLAlchemy 2, Alembic.
- Вход по email и паролю, подтверждение адреса и одноразовая ссылка для сброса пароля.
- Сессии: JWT и refresh token в `Secure`, `HttpOnly` cookies. Выход отзывает сессию сразу; операции изменения данных защищаются от CSRF.
- Служебные письма: Gmail API с отдельным разрешением пользователя на отправку от его Gmail.
- Размещение: React на Cloudflare Pages, FastAPI на Render Free. Pages проксирует `/api` к Render, чтобы браузер видел один адрес.
- Собственного домена нет; используется бесплатный адрес Pages. Регион хранения пользователь не ограничивал.
- Текущий бюджет: $0/месяц. Платные сервисы и ИИ не подключаются без отдельного согласования.
- Первые направления с готовыми материалами после технической основы: спорт и питание.
- Итоговая платформа должна содержать готовые материалы во всех заявленных направлениях; первый этап остаётся только технической основой.
- Программы и планы находятся внутри своих направлений. Общий список задач — отдельный инструмент; «Мой день» показывает занятия из планов напрямую, без автоматического создания копий в задачах. Это уточнение пользователя заменяет прежнее требование документа о связанных задачах из тренировок.
- Спортивная программа подбирается из заранее подготовленных и проверенных цельных программ по понятным правилам. Анкета о цели, уровне, ограничениях, месте, оборудовании и времени находится на сайте. Если подходящей программы нет, платформа сообщает об этом, а не выдаёт случайный план.
- Готовые программы, рецепты и учебные материалы хранятся в версионируемых файлах проекта. Для изменения опубликованных материалов требуется новая публикация приложения; личные ответы, записи и прогресс хранятся в PostgreSQL.
- Первое наполнение спорта: программы для снижения веса с акцентом на сохранение мышц, с отдельными проверенными вариантами для дома без оборудования, улицы и зала. Это цель, выбираемая внутри сайта, а не личный параметр, записанный за пользователя. Другие цели и неподдерживаемые ограничения получают явное состояние «подходящей программы пока нет».

- 10 октября 2026: стартовое программирование — Java; английский — маршрут A2 → B2; профессия — Java backend-разработчик (прямой выбор пользователя).

Формулу, ограничения её применения и источники пищевой ценности проверять перед реализацией.
- «Обучение»: готовые материалы по выбранным направлениям программирования, последовательные уроки, примеры, упражнения и прогресс; книги, план чтения и дневник чтения согласно исходному заданию. - «Языки»: готовые маршруты изучения выбранных человеческих языков с уроками и упражнениями внутри платформы. Согласован английский A2 → B2: 24 занятия с аудио и повторением слов; язык программирования относится к «Обучению», а не к этому разделу.

«Задачи» и календарь — самостоятельные инструменты организации, не сферы. Карточки сфер ведут к их планам и материалам, а не заменяются фильтром общего списка задач.

Текущие доступные сферы открывают собственные страницы. «Здоровье», учёт расходов в «Финансах», «Личное» и книги внутри «Обучения» реализованы локально. Локально добавлены Java, английский A2 → B2 и Java backend. Они содержат конечные стартовые маршруты, а не обещание всех возможных материалов или независимой оценки квалификации.

## Следующий этап: здоровье

- Навигация показывает шесть согласованных сфер. «Здоровье» открывает две работающие части — спорт и питание. Остальные сферы до их наполнения обозначены как следующие этапы и не перенаправляют в фильтр задач.
- Спорт: после анкеты сервер выбирает только совместимую цельную программу по цели, уровню, месту, оборудованию, дням, времени и ограничениям. Страница показывает причину выбора, расписание, разминку, упражнения с техникой, упрощением и заменами, завершение занятия. Журнал хранит фактическое выполнение по датам. Изменение анкеты сначала показывает новый вариант; замена требует подтверждения и не удаляет историю.
- Дополнение к спортивному подбору: наряду с прежними программами на 2–3 дня доступны отдельные четырёхдневные циклы PUSH/PULL/LEGS/UPPER для дома и зала на 60 минут. Расписание цикла — понедельник, вторник, четверг, суббота, как в предоставленном пользователем прежнем плане. Домашний вариант требует штангу и лёгкие гантели, не предполагает скамью или стойку; упражнения со штангой допускаются только при безопасной подаче и подходящем весе, с указанными заменами. Зальный вариант среднего уровня сохраняет жим и приседание со штангой с требованием страховочных ограничителей. Программы имеют новые идентификаторы и версию каталога; сохранённые снимки прежних планов и журналы не меняются.
- Для домашних занятий среднего уровня со штангой и лёгкими гантелями добавлены отдельные восьминедельные маршруты на 2, 3 и 4 дня. Экран активного плана показывает календарь всех недель, занятия по выбранным дням и совет на текущую неделю по журналу сложности и выполнения. Нагрузка по весу не назначается без данных о доступных блинах и подготовке; сохранённые четырёхнедельные снимки остаются неизменными.
- Питание: анкета содержит возраст, рост, вес, активность, цель и параметры используемой формулы, а также пищевые ограничения. Калькулятор даёт ориентировочную оценку по опубликованной формуле Mifflin–St Jeor и явно показывает допущения; обычный расчёт предназначен для взрослых, не применяется при беременности и грудном вскармливании или при неподдерживаемых особых состояниях. Показатели активности опираются на категории FAO/WHO/UNU. Подбор блюд учитывает ограничения; при нехватке совместимых рецептов готовый рацион не выдумывается.
- Библиотека рецептов содержит реальные ингредиенты с количеством и состоянием до/после приготовления, шаги, время, порции и вычисленные калории/БЖУ. Состав продуктов сверяется с USDA FoodData Central; вместе с материалами хранится идентификатор/ссылка источника и версия данных. Меню на день/неделю составляется только из совместимых блюд. Изменение порции и блюда пересчитывает дневные показатели и покупки. Фактически съеденное и записи веса хранятся отдельно от плана.
- «Мой день» получает ближайшую тренировку и меню напрямую из планов. Эти действия не создают копии в общем трекере задач.

Источники для проверки перед публикацией: [WHO о физической активности](https://www.who.int/publications/i/item/9789240014886), [NIDDK об ограничениях расчётов веса](https://www.niddk.nih.gov/health-information/weight-management/body-weight-planner), [публикация Mifflin–St Jeor](https://pubmed.ncbi.nlm.nih.gov/2305711/), [FAO/WHO/UNU об уровнях активности](https://www.fao.org/4/y5686e/y5686e07.htm), [USDA FoodData Central и лицензия](https://fdc.nal.usda.gov/api-guide/).

## Расширение материалов и интерфейса — предложение на согласование

Исследованные примеры дают идеи для сценариев, а не готовый контент для переноса. Материалы, тексты, упражнения, изображения и оформление платформы создаются самостоятельно; внешние источники используются для проверки фактов и указываются возле материала. Платные API, чужие аккаунты и внешние подписки не требуются. Основное содержимое остаётся в версионируемых файлах проекта, личные ответы и прогресс — в базе согласно согласованной архитектуре.

- **Здоровье:** расширять цельные программы только после проверки совместимости условий. На странице занятия разрешить заменить отдельное упражнение лишь заранее описанной совместимой альтернативой для того же оборудования и нагрузки, сохраняя исходную программу и журнал. В «Питании» оставить только библиотеку рецептов, граммы и число порций; добавить выбор по приёму пищи и поиск по названию/ингредиенту. Калькулятор остаётся на отдельном маршруте. Не возвращать меню, покупки и пищевой журнал в основной экран питания без нового запроса пользователя. Пример механики: [Fitbod — замена упражнений](https://help.fitbod.me/hc/en-us/articles/360006335593-Editing-Workouts-in-Fitbod), [Centr — порции и замены блюд](https://help.centr.com/en-US/articles/nutrition-and-meals-345224).
- **Обучение:** дополнить Java авторскими объяснениями, запускаемыми локально примерами, практикой и разбором типичных ошибок. После проверки ответа показывать конкретную тему для повторения; завершённые уроки оставлять доступными. Книги сохраняют собственные планы чтения, заметки и следующий отрезок. Пример механики прогресса: [Khan Academy](https://support.khanacademy.org/hc/en-us/articles/360032987591).
- **Профессия:** развивать маршрут Java backend через небольшие реальные проекты с входными требованиями, ожидаемым результатом, контрольным списком проверки и возможностью повторить этап. Сайт фиксирует самостоятельную работу, но не заявляет экспертную проверку кода или готовность к трудоустройству.
- **Языки:** развивать маршрут английского A2–B2 короткими авторскими текстами, упражнениями и повторением ошибок; не объявлять уровень подтверждённым только по завершению уроков. Пример последовательного маршрута и повторения: [Duolingo](https://blog.duolingo.com/spaced-repetition-for-learning/).
- **Финансы:** к ручному учёту добавить простой вывод по выбранному месяцу: крупнейшая категория, изменение относительно прошлого месяца в той же валюте и переход к связанным расходам. Сохранять раздельные валюты и не трактовать статистику как финансовый совет. Пример представления динамики: [YNAB](https://support.ynab.com/en_us/spending-trends-H1inlhzAc).
- **Личное:** организовать существующие авторские гайды в короткие последовательности с конкретным следующим действием и возможностью выбрать другой материал; дневник и личные события остаются приватными. Пример формата коротких курсов: [Headspace](https://www.headspace.com/content/topics/courses-and-singles/58).

**Единое правило интерфейса:** внутри каждой сферы первым показывать текущий план и ближайший шаг, ниже — материалы и возможность сменить неподходящий вариант. Историю, параметры подбора и справочные данные раскрывать по запросу. Сохранять все шесть сфер и отдельные «Задачи». Последнее уточнение пользователя от 11 октября: визуальную систему брать с самого сайта Awwwards, а не с присланного изображения банковского приложения. Поэтому направление интерфейса — светло-серое поле, чёрная крупная типографика, горизонтальная навигация, спокойные монохромные поверхности и компактная мобильная панель. Редакционные приёмы адаптируются к рабочей платформе; чужие логотип, изображения и точный макет не копируются. Состояния загрузки/ошибки и адаптация для телефона обязательны.

**Проверка принятия:** пользователь может открыть готовый материал без внешнего поиска, понять следующий шаг, увидеть источник фактических утверждений, изменить неподходящий вариант и сохранить историю; смена не создаёт копии в «Задачах». Количество материалов не выдаётся за полноту маршрута: конечные стартовые курсы и неподдерживаемые условия обозначаются явно. Новые личные данные и миграции проектируются только в рамках уже согласованного backend и проверяются на изоляцию аккаунтов.

## Следствия для реализации

- Секреты Gmail, Neon и подписи JWT хранятся только в переменных среды backend и не попадают в исходники, браузерный код и логи.
- Пароли хешируются Argon2id. Токены подтверждения и сброса одноразовые, в базе хранятся только их хеши.
- Access JWT содержит идентификатор сессии. FastAPI проверяет действующую сессию в PostgreSQL при каждом защищённом запросе, чтобы отзыв сработал сразу.
- Личные записи изолируются по текущему пользователю на сервере. Публичный учебный контент хранится отдельно от прогресса.
- Бесплатные тарифы имеют лимиты; Render засыпает после простоя. Без платёжного метода Render останавливает сервис при исчерпании бесплатного лимита вместо списания денег.

## Дополнение: личный зашифрованный архив — согласовано 10 октября 2026

### Назначение и границы

В профиле пользователь вручную скачивает архив своих данных и вручную загружает его для восстановления. Другой сервис, фоновое расписание и хранилище архивов не добавляются. Архив содержит настройки профиля (имя, часовой пояс, видимость сфер и разделов, валюту финансов), задачи с подзадачами и выполнениями, все планы и журналы спорта/питания, категории и расходы, личные записи, книги и журнал чтения, учебные планы, попытки, черновики и повторения. Сохраняются активные, архивные и мягко удалённые записи, даты, идентификаторы и снимки материалов. Пароль, его хеш, email-токены, сессии, CSRF и служебные события входа не экспортируются. Публичные версии программ, рецептов и курсов остаются в файлах приложения; архив хранит личные снимки, необходимые для истории.

Архив относится к одному нормализованному email. При восстановлении в заново созданном аккаунте с тем же email внутренние `user_id` переводятся на ID текущего аккаунта; связи между личными записями сохраняются. Другой email не принимается. Пользователь должен иметь действующий вход в аккаунт, поэтому при полной потере базы сначала нужно заново создать и подтвердить аккаунт; без рабочей отправки письма этот способ восстановления недоступен.

### Формат и защита

FastAPI создаёт версионированный архив со случайными солью и nonce. Ключ выводится из **введённого при скачивании текущего пароля входа** через scrypt; содержимое шифруется и проверяется AES-256-GCM. Пароль проверяется по хешу аккаунта при экспорте, но ни пароль, ни ключ, ни открытый JSON не сохраняются на сервере, в браузерном хранилище или логах. Если пароль аккаунта впоследствии сменится, прежний архив открывается прежним паролем. Пароль нельзя восстановить из архива. Новое приложение должно понимать версию формата и явно отказывать неизвестной версии. Добавляется библиотека `cryptography`; не применяется собственная реализация криптографии. Ограничение на файл и расшифрованные данные — 8 МиБ каждое; строгая проверка структуры, типов, имён таблиц, связей и принадлежности аккаунту выполняется до изменения базы. Ошибки пароля и повреждения файла показываются одинаково.

Криптографические примитивы и параметры сверяются с документацией [`Scrypt`](https://cryptography.io/en/stable/hazmat/primitives/key-derivation-functions/) и [`AESGCM`](https://cryptography.io/en/stable/hazmat/primitives/aead/); nonce для одного ключа никогда не используется повторно.

### Пользовательский сценарий и транзакция

1. «Скачать архив»: повторно ввести текущий пароль, получить бинарный файл через защищённый POST с CSRF, сохранить его локально. Сервер не хранит копию.
2. «Проверить архив»: выбрать файл и ввести пароль, которым он был создан. Сервер расшифрует файл и покажет только перечень разделов, количество записей и дату создания. Это не меняет данные. Проверка выдаёт короткоживущий подписанный маркер предпросмотра с ID сессии, отпечатком текущего состояния и SHA-256 загруженного файла.
3. Перед кнопкой замены пользователь скачивает **свежий архив текущего состояния** с текущим паролем. Для этого запрос передаёт маркер предпросмотра; сервер сверяет неизменность состояния и вместе с файлом выдаёт одноразовый маркер восстановления, привязанный к той же сессии и исходному файлу. Интерфейс требует явного подтверждения, что файл сохранён. Простой флаг из браузера недостаточен.
4. «Восстановить»: повторно отправить тот же файл и пароль архива, текущий пароль аккаунта и одноразовый маркер. Сервер заново проверяет пароль, файл, структуру, email и неизменность текущего состояния, удаляет только личные записи этого аккаунта и вставляет записи архива в порядке зависимостей **одной транзакцией**. Сбой откатывает транзакцию целиком. Другие аккаунты, пароль входа и текущие сессии не затрагиваются. После успеха интерфейс обновляет данные сфер.

Сервер подписывает маркеры существующим секретом JWT; срок их действия — 10 минут. Маркер восстановления содержит случайный идентификатор, ID сессии, SHA-256 исходного файла и канонический отпечаток текущих данных. Использованный идентификатор сохраняется в небольшой служебной таблице внутри той же транзакции, поэтому повторное применение отклоняется. Сами архивы и маркеры не экспортируются. Ошибка сети или несовпадение отпечатка оставляет личные данные без изменений и предлагает начать проверку заново.

В PostgreSQL все изменения личных данных и операции с архивом удерживают блокировку строки пользователя до завершения транзакции; это не даёт параллельной записи попасть между проверкой отпечатка и заменой. Ленивая запись стандартных финансовых категорий использует ту же блокировку и не завершает транзакцию посреди другого изменения.

### Проверка

Тесты должны покрывать полный круг export → preview → pre-restore backup → replace, смену пароля между экспортом и восстановлением, неверный пароль/битый файл/неизвестную версию, превышение размера, повреждённые ссылки, чужой email и пользователя, повтор маркера, изменение данных между предпросмотром и заменой, сбой в середине транзакции и сохранность пароля/сессий. Проверить SQLite в тестах и миграцию служебной таблицы; перед публикацией отдельно проверить PostgreSQL Neon и обновление интерфейса после восстановления. После локального успеха не объявлять онлайн-восстановление проверенным до реального прогона на развёрнутом сайте.

## Анкета по шести сферам и локальная библиотека (11.10.2026)

После первой регистрации пользователь проходит шесть коротких шагов: здоровье, обучение, профессия, языки, финансы, личное. Сервер строит предварительный подбор из существующих версионированных программ, рецептов, книг и гайдов; до кнопки «Начать» планы не создаются. Неподдерживаемый спортивный или учебный вариант получает явный статус «нет готового маршрута». После подтверждения сервер сохраняет ответы и создаёт только совместимые планы одной транзакцией. При повторной анкете замена требует подтверждения; старые спортивные и учебные планы архивируются, журналы и выполненные уроки остаются доступны. Анкету можно снова открыть из профиля. Существующие до миграции аккаунты сохраняют доступ без обязательного прохождения анкеты.

Рецепты при наличии ответов фильтруются по вегетарианству и времени приготовления, с переключателем показа всех. Книжная подборка открывается с выбранного интереса. Гайды финансов и личного ставят рекомендованный материал первым. Сам калькулятор калорий остаётся отдельным от рецептов.

Восемь произведений с истёкшим сроком охраны оригинального русского текста сохранены в `backend/app/content/ebooks`: «Хамелеон», «После бала», «Алые паруса», «Вишнёвый сад», «Муму», «Капитанская дочка», «Записки охотника», «Бежин луг». EPUB получены через экспорт Викитеки; ссылки на страницы и сведения о правах записаны в `book_suggestions.json` и `ebooks/README.md`. Все восемь книг имеют локальное чтение по частям и скачивание EPUB. Новые файлы добавляются в белый список после проверки прав.

## Личный ИИ для подбора и развития плана — согласовано 12 октября 2026

### Назначение и источник материалов

После анкеты по шести сферам платформа предлагает индивидуальный план. ИИ компонует объяснения и следующие шаги только из совместимых, проверенных и версионированных материалов общей библиотеки. Сначала детерминированный подбор применяет обязательные фильтры и показывает, где материалов не хватает; ИИ не превращает такой пробел в вымышленную программу. Создание и расширение библиотеки, проверка её охвата для типовых профилей и отзыв ошибочного материала остаются отдельным редакционным процессом.

FastAPI передаёт модели только минимальные сведения, нужные для выбранных сфер: ответы анкеты, доступные материалы с их ID/версиями и релевантный прогресс. Сырой дневник, финансовые операции, пароль и архив не включаются в запрос. Результат модели — структурированное предложение со ссылками на ID материалов и объяснением выбора. Сервер повторно проверяет совместимость, актуальность и ограничения каждого выбранного материала; недопустимый результат отклоняется. ИИ не придумывает калорийность, аллергенный состав, медицинские допуски, противопоказания или недостающие упражнения. При ограничениях здоровья действуют уже согласованные правила безопасного подбора.

### Обновление плана и контроль пользователя

При завершении анкеты формируется предпросмотр; планы сохраняются только после действия «Начать». Затем система предлагает пересмотр раз в неделю на основании фактического прогресса и сразу после изменения цели или существенных ответов анкеты. Пользователь видит, какие занятия или материалы предлагается заменить и почему, и подтверждает изменение до записи. Сохранённые результаты и прежние версии плана остаются доступными. Повторный запрос не должен создавать дубли планов или стирать историю; запись изменений выполняется атомарно по правилам существующего механизма подбора.

В недельном обзоре тренировки сравниваются с расписанием активного плана за завершённую неделю. Перенос занятия на другой день той же недели засчитывается по ID занятия. Если при плане от трёх занятий записано не больше половины, интерфейс предлагает уменьшить частоту на один день в неделю; при полном выполнении с высокой субъективной сложностью предлагает сохранить ритм и оценить восстановление. Отсутствие записи не трактуется как доказательство невыполненной тренировки. Кнопки открывают соответствующий шаг анкеты, где подбор проверяется заново; другие сферы по умолчанию пропущены и не заменяются. Смена спорта требует отдельного подтверждения.

Во время тренировки введённые подходы, вес, сложность и заметка автоматически сохраняются как личный черновик по плану, дате и занятию. После повторного открытия формы черновик восстанавливается. Черновик не считается выполненной тренировкой и не влияет на аналитику или серию активности. Действие «Завершить тренировку» отдельно проверяет результаты, создаёт запись в истории и удаляет черновик. Черновики входят в личный зашифрованный архив; старые архивы без них восстанавливаются с пустым списком.

На экране «Мой день» аналитика показывает четыре завершённые недели: число дней с записанными действиями без повторного счёта одного дня, число записанных тренировок, выполнение отдельных задач и распределение действий по шести сферам. При отсутствии записей отображается пустое состояние без выдуманного прогресса. Подробный недельный обзор и оценка тренировочной нагрузки доступны в раскрываемом блоке. Все показатели рассчитываются на сервере только из записей текущего аккаунта.

Пользователь может оценить нагрузку активного плана за завершённую неделю: «подходит», «слишком легко» или «слишком сложно». Оценка хранится для пары план/неделя и может быть изменена; другие аккаунты её не видят. В следующий локальный ИИ-предпросмотр передаётся только код оценки за последнюю завершённую неделю активного плана вместе с агрегированным прогрессом, без текста заметок. Оценка не меняет план автоматически. Она входит в личный зашифрованный архив; архивы, созданные до добавления оценок, восстанавливаются с пустой историей оценок.

Если локальная модель недоступна, работает обычный проверяемый подбор по правилам библиотеки. Отсутствие подходящего материала явно показывается пользователю, без фиктивного плана. Качество ИИ оценивается на типовых профилях, пограничных ограничениях и случаях изменения цели; покрытие каталога измеряется отдельно от качества генерации.

### Развёртывание и бюджет

Для текущего личного использования при бюджете $0 согласован **локальный запуск модели на компьютере пользователя через Ollama** и обращение к ней из FastAPI. На личном Mac проверена `qwen3:4b-instruct`; API умеет необязательное предложение из сохранённого предпросмотра при `LOCAL_AI_ENABLED=true` и `SHARED_MATCHING_ENABLED=true` в development. В новом предпросмотре модель учитывает только агрегированные записи тренировок и учебных попыток за последнюю завершённую неделю. Недельный экран ведёт к повторной анкете; предложение не заменяет план до подтверждения. Подбор по правилам остаётся обязательным запасным путём. Модель не получает доступ к интернету или базе напрямую и не может самостоятельно публиковать материалы. Автоматическая генерация новых упражнений или уроков по прогрессу не включена.

Для будущего публичного продукта локальная модель на компьютере владельца не считается готовой инфраструктурой для всех пользователей. Можно отдельно исследовать выполнение в браузере на поддерживаемых устройствах (WebLLM/WebGPU), учитывая несовместимые браузеры и слабое оборудование. Серверный ИИ, платный API, отправка личных данных внешнему поставщику и связанные расходы требуют нового согласования архитектуры и условий приватности перед внедрением.

### Порядок первого этапа наполнения и подключения ИИ

1. Составить отчёт по вариантам ответов анкеты во всех шести сферах. Для каждого сочетания определить, есть ли полный маршрут на заявленный срок, только отдельные материалы или ничего подходящего. Текущие 108 синтетических профилей — стартовая проверка, а не доказательство полного охвата реальных пользователей; отдельно проверить допустимые сочетания и пограничные случаи.
2. По обнаруженным пробелам добавить цельные спортивные программы для разных целей, уровней, мест и доступного оборудования. При ограничениях здоровья не назначать универсальную силовую программу. Проверить, что рецепты остаются разнообразными с учётом ограничений, цели питания и времени приготовления.
3. Проверить длительность и полноту маршрутов Java, Go, английского и Java backend, затем добавить недостающие главы с практикой и проверкой результата. Для остальных сфер проверить, что подобранные материалы поддерживают понятный следующий шаг. Число записей каталога само по себе не означает достаточную глубину.
4. После проверки охвата подключить локальный ИИ к личной последовательности и пересмотру по прогрессу согласно правилам выше. ИИ использует только существующие подходящие материалы; для незакрытых вариантов анкеты показывается явный пробел.

Первый рабочий выпуск этого направления ограничен проверяемой картой охвата, закрытием выявленных пробелов и локальной персонализацией из подтверждённой библиотеки. Расширение на публичный сервис и платную инфраструктуру рассматривается отдельно.

## Актуальные версии учебных маршрутов и каталог спорта — 12 октября 2026

Новые планы получают Java v2 (14 занятий), Go v2 (32), английский v2 (27) и Java backend v3 (14). Старые планы используют версии, с которыми были созданы; уроки и сохранённые результаты не переписываются. Количество занятий на странице «Обучение» берётся из каталога либо активного плана.

Каталог спорта дополнен шестью четырёхдневными уличными программами для трёх целей и двух уровней при наличии перекладины, скамьи и резинки. Внутри недели чередуются верх и низ тела. Отмеченные ограничения здоровья, отсутствующее оборудование, недостаточное время и несовместимое расписание по-прежнему дают явный отказ в автоматическом назначении. Структурная проверка каталога и источников не заменяет индивидуальную оценку специалиста.
