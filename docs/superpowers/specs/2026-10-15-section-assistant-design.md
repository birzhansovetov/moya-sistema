# Помощник во всех разделах

Дата: 15 октября 2026. Основа: согласованная пользователем схема общей помощи и действующий бесплатный Gemini с объяснениями публичных материалов.

## Цель

Пользователь понимает текущий раздел, получает объяснение материала и видит доступное действие. Помощник доступен на каждой странице приложения, включая анкету. Он не меняет планы, записи, настройки или результаты занятий самостоятельно.

## Подход

Расширить существующий серверный обработчик облачных объяснений и использовать одну общую панель. Отдельные чаты для каждой сферы дублировали бы проверки и интерфейс. Чат со свободным текстом потребовал бы другого режима обработки личных данных и не входит в этот выпуск.

Существующий StudyHelp с последовательностью подсказок и проверкой принадлежности урока сохраняется. Общая панель объясняет раздел и публичные материалы; она не обходит ограничения учебных подсказок.

## Интерфейс

- Общая кнопка «Помощник» в оболочке приложения; такая же панель доступна в анкете. На экранах входа и восстановления — только помощь по функциям регистрации, без отправки введённых значений.
- На компьютере боковой Dialog, на телефоне Dialog на весь доступный экран. Использовать существующие Button, Dialog, Card и дизайн-токены. Без декоративных стрелок.
- Заголовок текущего раздела, 3–5 готовых вопросов, ответ с подписью источника и названного материала. На стартовом экране нет длинного описания или пустого поля чата.
- Для объяснения конкретного материала рядом с ним доступно действие «Объяснить». Материал выбирается из серверного каталога, текст из DOM не отправляется.
- Результат: «Объяснение ИИ · Gemini» или «Готовая подсказка». Кнопки «Помогло / Не помогло». При смене страницы старый ответ очищается, поздний ответ предыдущей страницы игнорируется.
- Видимые состояния загрузки, ошибки и повторной попытки; размер кнопок не скачет. Фокус переносится в Dialog и возвращается при закрытии; Escape закрывает окно, сообщения доступны экранному чтецу.
- Русский интерфейс, существующий шрифт с поддержкой казахских букв. Длинный текст переносится, диалог прокручивается независимо от страницы.

## Покрытие

| Страницы | Готовая помощь |
|---|---|
| Мой день, разделы | Как начать, отметить прогресс, найти нужную сферу |
| Обучение, Java, Go, профессия | Как устроен курс; объяснения опубликованной теории; учебные подсказки через действующий StudyHelp |
| Английский, казахский, корейский, турецкий, испанский | Правила, примеры, словарь из выбранного урока; без раскрытия ответов проверочных заданий |
| Здоровье, спорт | Техника конкретного упражнения, подходы, отдых; объяснение только перечисленных в каталоге замен |
| Питание | Приготовление рецепта, единицы и порции по каталогу |
| Калории | Значение полей, формула, приблизительность расчёта; без отправки параметров тела и результата |
| Финансы | Учёт доходов и расходов, категории, бюджет по готовым гайдам; без чтения операций и сумм |
| Книги | Жанры и публичные карточки библиотеки, использование читалки; без загрузок пользователя и его заметок |
| Дневник | Использование настроения и активностей, готовые вопросы для самостоятельной записи; без чтения дневника |
| Задачи, календарь | Создание, даты, повторения только в пределах реализованных функций |
| Профиль, анкета, авторизация | Объяснение настроек и вопросов формы; без отправки ответов, email, паролей или токенов |

Личная персонализация, подбор по ограничениям здоровья и изменения плана остаются в существующей серверной логике. Помощник может предложить локальную ссылку на соответствующий экран, но не объявляет персональное назначение от имени модели.

## Контракт сервера и приватность

Добавить общий маршрут `/api/assistant/topics` и `/api/assistant/explain`. Запрос объяснения содержит только код раздела, ID готового вопроса и при необходимости ID/версию публичного материала. Не допускаются свободный текст, поля личных записей или присланное клиентом содержимое. Неизвестные поля отвергаются.

Сервер разрешает ID через явный реестр адаптеров: гайды, упражнения, рецепты, публичные карточки книг, теория и словарь уроков, справка интерфейса. Не передавать модели задания с эталонными ответами. Отозванные/недоступные материалы не используются. Изменение версии выбранного материала требует обновления списка тем.

Внешний payload содержит только проверенный публичный фрагмент, тип объяснения и язык. Нет идентификаторов аккаунта, IP, маршрута с параметрами, анкеты, прогресса, финансов, здоровья, личной книги или дневника. Модель переформулирует содержание и не добавляет новые назначения, диагнозы, инвестиционные советы, рецепты или упражнения. В спорте, питании и финансах показывается короткая оговорка о справочном характере помощи.

Аутентифицированные обращения используют существующие auth/CSRF и ограничение частоты. Публичная помощь авторизации возвращает готовую справку без вызова Gemini. Общая и учебная помощь делят облачный лимит аккаунта, глобальный лимит транспорта, блокировку, таймаут и кэш; новые имена событий должны помещаться в VARCHAR(24).

Сохранить `CLOUD_AI_ENABLED` как общий выключатель. Добавить список разрешённых сфер для поэтапного включения. Без ключа, при выключенном флаге, исчерпании квоты, ошибке или невалидном ответе всегда доступна готовая справка.

## Реестр справки и обратная связь

Справка интерфейса хранится в версионируемом JSON: ID, раздел, вопрос, готовый ответ, допустимые ссылки на внутренние маршруты, дата проверки. Адаптеры существующих материалов используют их текущие версии, не создают отдельные несинхронные копии.

Для оценки хранить только идентификатор запроса, владельца для проверки доступа, код темы, публичный ID/версию материала, источник, модель/версию промпта, задержку и булеву оценку. Не хранить текст личного запроса или ответа. Срок хранения служебных записей — 30 дней с очисткой существующей задачей; продление не требуется для работы материалов. Повторная оценка отклоняется. Отчёт редактора агрегирует обращения и долю запасных ответов по публичным темам.

## Порядок внедрения

1. Проверить реестр всех маршрутов, справку и допустимые материалы каждого раздела.
2. Обобщить транспорт без изменения поведения StudyHelp; добавить общий контракт, лимиты и тесты приватности.
3. Добавить единую панель в оболочку, анкету и авторизацию; подключить объяснения материалов.
4. Проверить все маршруты, ошибки, клавиатуру, длинные подписи и адаптивность.
5. Опубликовать frontend/backend и выполнить настоящий запрос через публичный адрес. Запасной ответ не считается подтверждением работы Gemini.

## Критерии готовности

- Все перечисленные страницы имеют работающую помощь; ни один известный маршрут не попадает в неопределённый раздел.
- Для каждого типа каталога есть хотя бы один проверенный пример; все пять языков проверены отдельно.
- Тест транспорта подтверждает отсутствие личных полей и свободного текста; чужая оценка, неизвестные ID, устаревшая версия и отозванный материал отвергаются.
- Учебная лестница подсказок не обходится общей панелью. Тесты «игнорируй правила» и невалидного ответа дают безопасный запасной фрагмент.
- При выключении флага и HTTP 402/429/таймауте материалы и справка остаются доступны. Лимит общей помощи нельзя обходить переключением разделов.
- Проверены ширины 360, 390, 768, 1440 px и настоящий масштаб 200%; длинные русские и казахские подписи, фокус, переполнение и мобильная навигация. В отчёте отдельно указаны фактически проверенные поверхности.
- На публичном сайте подтверждены настоящий `source=cloud_ai`, подпись источника и отсутствие локального Ollama в потоке друзей. Тестовые записи удалены после проверки.

## Риски и границы

Бесплатная квота не гарантирует ответы каждому пользователю; общий кэш и готовая справка сохраняют полезность. Модель может исказить смысл: ограниченные фрагменты, проверка результата, отсутствие автоматических действий и оценка пользователя снижают риск, но не доказывают фактическую точность каждого ответа.

В этот выпуск не входят свободный чат, анализ личных данных, генерация персональных тренировок/диет, автоматическая смена планов, медицинские рекомендации, инвестиционные решения, анализ загруженных книг и выполнение пользовательского кода. Для них нужен отдельный согласованный режим данных и провайдера.
