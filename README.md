# Моя система

Личная платформа. Реализованы аккаунт, профиль, задачи, календарь и «Мой день», а также «Здоровье» со спортом и питанием, учёт расходов в «Финансах», «Личное» и книги внутри «Обучения».

Локальные автоматические проверки покрывают API и интерфейс. Шесть сфер содержат готовые стартовые материалы: здоровье, обучение с книгами и Java, профессию Java Backend, английский A2–B2, финансы и личное развитие. Планы находятся внутри разделов; задачи и календарь остаются отдельными инструментами. Сайт пока используется локально. Реальная отправка почты, хранение в Neon и работа на Cloudflare Pages/Render требуют настройки сервисов и не проверены.

## Состав

- `backend/` — FastAPI, SQLAlchemy, Alembic.
- `frontend/` — React, TypeScript, Vite, CSS Modules; Pages Function проксирует `/api`.
- `docs/architecture.md` — согласованные архитектурные решения.
- `backend/app/content/` — готовые программы тренировок, инструкции упражнений, продукты USDA SR Legacy 2018-04 и рецепты в версионируемых JSON-файлах. Личные планы и журналы хранятся отдельно в базе.

## Здоровье

- **Спорт:** анкета на сайте подбирает совместимую программу из каталога для дома, улицы или зала; доступны разные цели, уровни и частота 2–4 раза в неделю. Нужны совместимые цель, место, оборудование, время и расписание. Ограничения по здоровью и неподдерживаемые условия дают явный ответ «программы нет». Замена плана подтверждается; записи тренировок сохраняются.
- **Питание:** калькулятор использует Mifflin–St Jeor и категории активности FAO/WHO/UNU. Возраст вне 19–78 лет, беременность, грудное вскармливание и особые состояния не получают готовый расчёт. Цель калорий и БЖУ — ориентир, который можно пересмотреть по журналу веса. Рецепты содержат шаги, порции и ссылки на USDA FoodData Central; пищевые значения относятся к исходным продуктам до приготовления. Меню учитывает предпочтения, аллергены, исключённые продукты и время готовки. Изменения порций и блюд пересчитывают день и список покупок; фактически съеденное записывается отдельно.
- **Мой день:** показывает действия из сохранённых планов напрямую, без создания копий задач и изменения счётчиков задач.

## Финансы

- Расходы: сумма, категория, дата, комментарий и валюта; история с поиском, периодом, категориями и страницами. Можно изменить запись, удалить и восстановить её, в том числе из списка удалённых.
- Итоги за сегодняшний день и текущую неделю считаются в часовом поясе профиля; месячные итоги и доли категорий относятся к выбранному месяцу. Фильтры истории не меняют месячную аналитику.
- KZT, USD, EUR, RUB и GBP учитываются раздельно, без конвертации. Основная валюта задаёт значение для новых расходов. Суммы API передаёт десятичными строками и хранит в целых сотых; повтор сохранения с тем же ключом не создаёт дубликат.
- Свои категории можно создавать и переименовывать. Доходы, банковские подключения и бюджеты в этот этап не входят. Встроены два гайда по точному вводу расходов и месячному разбору записей.

## Личное и чтение

- «Личное»: приватный дневник с необязательным настроением; события, отдых, хобби, поездки и эксперименты «Хочу попробовать» с датой, выполнением и впечатлениями. Поиск, фильтры, редактирование, удаление и восстановление. Три авторских пошаговых гайда внутри сайта.
- Датированные события/эксперименты выводятся в календарь и «Мой день» напрямую. Текст дневника, настроение и впечатления туда не передаются. Счётчики задач остаются отдельными.
- «Обучение → Книги»: карточки книг, статусы, даты, темп чтения и следующий отрезок; свободные заметки и шесть необязательных вопросов; поиск и история страниц. Последняя по дате активная запись со страницей задаёт закладку; удаление/восстановление заметки пересчитывает её. Смена темпа сохраняет историю.
- Два авторских гайда по чтению и четыре стартовые литературные рекомендации с вопросами. Ссылки: [Хамелеон](https://www.culture.ru/books/977/khameleon), [После бала](https://www.culture.ru/books/518/posle-bala), [Алые паруса](https://www.culture.ru/books/86/alye-parusa), [Вишнёвый сад](https://mybook.ru/author/anton-pavlovich-chehov/vishnevyj-sad/). Дополнительно доступен [каталог бесплатных книг MyBook](https://mybook.ru/catalog/books/free/); доступность отдельного издания нужно проверять на его странице. Полные тексты книг не копируются в проект; материалы для самостоятельного разбора находятся внутри сайта. Число страниц вводится по изданию пользователя.
- Все семь гайдов и подборки — версионируемые JSON в `backend/app/content/`; личные записи — в базе. Планы чтения не подтверждают освоение учебного курса.

## Локальная разработка

Нужны Python 3.12+ и Node 20.19+ или 22.12+. Для локального API можно использовать SQLite; для публикации нужен PostgreSQL Neon.

```sh
cd backend
python -m venv .venv
.venv/bin/pip install -e '.[dev]'
export DATABASE_URL=sqlite:///./local.db
export JWT_SECRET='a-local-development-secret-with-32-plus-characters'
export FRONTEND_ORIGIN=http://127.0.0.1:5173
export ENVIRONMENT=development
# Укажите GMAIL_* из backend/.env.example для отправки писем.
.venv/bin/alembic upgrade head
.venv/bin/uvicorn app.main:get_app --factory --reload --host 127.0.0.1 --port 8000
```

В другом терминале:

```sh
cd frontend
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173`. При регистрации вводится email; пароль задаётся после перехода по ссылке подтверждения из письма. Без настроенного Gmail API регистрация не отправит письмо и не завершит подтверждение адреса. Тесты используют почтовый адаптер без доступа к реальному Gmail.

Проверки:

```sh
cd backend && .venv/bin/python -m pytest -q
cd frontend && npm test && npm run build
```

## Резервная копия

В профиле можно вручную скачать зашифрованный архив личных данных (`.moya-backup`, до 8 МиБ). Для создания архива нужен текущий пароль входа. Для открытия сохранённого архива нужен пароль, действовавший **в момент его создания**: после смены пароля старый архив не откроется новым паролем.

При восстановлении выберите файл и введите пароль архива. Сайт покажет дату и состав файла. Затем введите текущий пароль входа, скачайте свежую копию нынешних данных и подтвердите, что она сохранилась. Только после этого станет доступна замена личных записей. Профиль входа и активные сеансы не заменяются. Храните архив и его пароль в безопасном месте: забытый пароль восстановить из файла нельзя.

Локальные тесты проверяют шифрование, целостность, изоляцию аккаунтов, лимит загрузки и откат ошибочной замены. Работа с опубликованным сервером и реальной базой Neon пока не проверена.

## Размещение без собственного домена

1. Создайте проект Neon Free и скопируйте PostgreSQL connection string. Для первого этапа Object Storage не нужен.
2. В Google Cloud включите Gmail API и настройте OAuth для отправки писем от своей почты. OAuth client ID, client secret и refresh token укажите только в Render. Для `gmail.send` нужен доступ к отправке; не передавайте секреты в чат или репозиторий.
3. Создайте Render Web Service из этого репозитория: root directory `backend`, build command `pip install -e .`, start command `alembic upgrade head && uvicorn app.main:get_app --factory --host 0.0.0.0 --port $PORT`. Добавьте переменные из `backend/.env.example`; `FRONTEND_ORIGIN` должен быть точным адресом Pages, `ENVIRONMENT=production`.
4. Создайте Cloudflare Pages проект из того же репозитория: root directory `frontend`, build command `npm ci && npm run build`, output directory `dist`. В Pages Functions задайте `BACKEND_ORIGIN` равным HTTPS-адресу Render, например `https://your-service.onrender.com`. При публикации Functions каталог `frontend/functions` должен находиться в корне Pages проекта.
5. Проверьте на адресе `pages.dev`: регистрацию, письмо, подтверждение, вход, перезагрузку, создание и повторное выполнение задачи, выход, восстановление пароля. Проверьте то же с отдельным вторым аккаунтом.

В Cloudflare Pages static routes исключены из вызова Function через `_routes.json`; `/api/*` идёт через прокси. Cookies устанавливаются для адреса Pages и не доступны JavaScript. Render Free может засыпать и запускаться с задержкой после простоя.

Секреты в репозитории не хранятся. Начните с `backend/.env.example` как списка переменных, не копируя реальные значения в отслеживаемые файлы.

## Общая библиотека и личный подбор

Новый подбор по шести сферам скрыт за `SHARED_MATCHING_ENABLED=false` по умолчанию. После ручной проверки лицензий, аллергенов, спортивных ограничений и клиентского сценария можно включить `true` на API. Каталог остаётся в JSON-файлах, личные ответы и планы — в базе. Предпросмотр живёт 30 минут и хранит полный список совместимых вариантов; повторный запуск с тем же выбором возвращает один результат.

Для личного локального ИИ установите Ollama, загрузите `ollama pull qwen3:4b-instruct` и убедитесь, что `http://127.0.0.1:11434/api/version` отвечает. После проверки общей библиотеки включите в локальном окружении `SHARED_MATCHING_ENABLED=true` и `LOCAL_AI_ENABLED=true` (`ENVIRONMENT=development`). Локальный запуск через `backend/.local/local_preview.py` на этом компьютере уже включает оба переключателя. `OLLAMA_MODEL` позволяет указать другую локально установленную модель. На экране предпросмотра ИИ предлагает ID только из сохранённого списка совместимых материалов; при повторном подборе учитывает агрегированные тренировки и учебные попытки за последнюю завершённую неделю. Человек применяет предложение отдельной кнопкой, затем подтверждает «Начать». Недоступная модель не мешает обычному подбору. Запрос к модели отправляется только на `127.0.0.1`; вне development локальный ИИ отключён.

Служебный отзыв материала выполняется из доверенной среды: `python -m app.content_admin revoke --kind sport --id ID --version VERSION --reason 'Причина' --actor OPERATOR`. Снятие отзыва — команда `restore` с собственной причиной. Все действия сохраняются в журнале. Отозванные материалы не назначаются заново; уже сохранённая история остаётся доступной с предупреждением.

Запускайте `python -m app.cleanup onboarding` раз в день в доверенном окружении с `DATABASE_URL`: команда удаляет просроченные снимки и записи повторной выдачи результата, сохраняя планы. CI выполняет `python -m app.coverage --check`; при намеренном обновлении каталога проверьте отчёт и выполните `python -m app.coverage --update` вместе с ревью изменений. Для отката нового интерфейса выключите `SHARED_MATCHING_ENABLED` и верните предыдущий выпуск файлов каталога; миграции и сохранённые снимки планов не удаляйте.


## Учебные маршруты

- `/education/java`: 14 занятий Java в актуальной версии; прежние планы на 12 занятиях сохраняются.
- `/languages`: 27 занятий английского A2/B1/B2, 27 локальных аудиофайлов, словарь и интервальное повторение; прежние планы на 24 занятиях сохраняются.
- `/profession`: 14 занятий Java backend в актуальной версии и приватные результаты; исторические планы на 8 и 12 занятиях сохраняются.

Маршрут Go содержит 32 занятия. В анкете выбираются блок, цель, дни, дата начала и время. Предпросмотр не создаёт план; замена явно подтверждается, старые результаты остаются в архиве. «Мой день» открывает конкретный урок с датой и ID плана, задачи не дублируются. Результаты, карточки и явно сохранённые черновики хранятся через FastAPI; необходимы миграции `c412_study` и `c413_study_drafts`. Черновик доступен после повторного входа, а подтверждённая попытка удаляет соответствующий черновик.

Сайт не исполняет пользовательский Java-код, не оценивает автоматически свободную речь/письмо и не выдаёт сертификат CEFR. Это стартовые самостоятельные маршруты, а не экспертная оценка навыка. Источники и формат материалов: [docs/study-content.md](docs/study-content.md). После неверного ответа показываются разбор и упражнение для повторения. Черновики удерживаются при переключении уроков и ошибках отправки; после полного обновления страницы восстанавливается только явно сохранённый черновик. Несохранённый ввод может потеряться. Проверка этапа: [docs/verification/2026-10-10-study.md](docs/verification/2026-10-10-study.md).
